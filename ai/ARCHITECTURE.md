# ARCHITECTURE

## 목적
이 프로젝트의 핵심 구조와 레이어 순서를 정의한다.
AI, 개발자, 실행 도구(Cursor 등)는 이 문서를 최상위 아키텍처 기준으로 삼는다.

## 현재 목표
- 채팅 시스템의 안정적인 기준선 확보
- 기능 추가보다 동기화 일관성 우선
- 모바일/랩톱 실기기 기준으로 검증

## 핵심 원칙
1. 기준선이 흔들리면 기능 추가를 중단한다.
2. 한 번에 한 레이어만 추가한다.
3. 실기기 검증이 끝나기 전 다음 단계로 넘어가지 않는다.
4. 정확성 경로와 편의 경로를 분리한다.
5. 롤백은 부분 추측 수정이 아니라, 검증된 기준선으로만 한다.

## 채팅 시스템 레이어 순서
### Phase 0
- 로그인
- 단일 채팅방
- 메시지 전송
- 전체 목록 조회(full fetch)
- F5 후 동일 상태 유지
- 모바일/랩톱 양방향 송수신 확인

### Phase 1
- realtime 추가
- 단, 정확성은 여전히 list/full fetch가 보장

### Phase 2
- partial fetch / polling / reconcile 추가
- full fetch 이후에만 허용

### Phase 3
- room 구조
- unread
- 숨김
- 관리자 기능

## 현재 금지
- 기준선 불안정 상태에서 새로운 기능 추가
- 여러 레이어 동시 변경
- 원인 미확정 상태에서 보정 코드 누적
